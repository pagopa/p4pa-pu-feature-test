    Given steps

    The Given steps below perform several checks internally. Steps that do a single, self-explanatory action are intentionally left out.

    a complex debt position with {po_size} payment options created by organization interacting with {pagopa_interaction}

    also: a debt position {dp_identifier} with {po_size} payment option and {installments_size} installments created by organization interacting with {pagopa_interaction}

    Creates a complex debt position (several payment options with installments) in one step. It:

    • gets the organization token and builds the payment options;
    • creates the debt position and checks it becomes UNPAID;
    • verifies presence in the GPD/ACA archive and the scheduled expiration workflow.

    a mixed debt position created by SIL for organization interacting with {pagopa_interaction} configured as follows

    Creates a mixed debt position via SIL in one step. It:

    • gets the SIL token and builds the mixed entity;
    • sends it through SIL and retrieves the resulting debt positions by IUV;
    • validates all data of generated debt positions (status, amounts, expiration workflow, ecc);
    • verifies presence as valid in the GPD/ACA archive.

    a notification created for the single installment of debt position {dp_identifiers}

    also: a notification created for the single installment of debt positions {dp_identifiers}, a notification created for the {installments_size} installments of debt positions {dp_identifiers}

    Creates a SEND notification for the selected installments. It:

    • builds the notification request (recipients and pagoPA payments) for the given debt positions;
    • gets a SEND token and posts the notification;
    • asserts the call succeeds and the notification is created in status WAITING.

    a payment reporting with outcome code 9 has been successfully processed for the installment created outside PU

    For a debt position created outside PU, uploads a payment reporting with outcome code 9 and checks, in one step, that it is processed and that the debt position is created correctly.

    a payment reporting with outcome code {outcome_code} has been successfully processed for the installment

    Uploads a payment reporting and checks it is processed, in one step:

    • uploads the file,
    • checks the debt position becomes REPORTED,
    • checks processing and (for outcome 9) that the receipt is created.

    a simple debt position created by organization interacting with {pagopa_interaction}

    also: a simple debt position of type {dp_type_org_code} created by organization interacting with {pagopa_interaction}, a simple debt position {dp_identifier} for citizen {citizen_identifier} created by organization interacting with {pagopa_interaction}

    Creates a simple, single-installment debt position in one step. It:

    • gets the organization token and builds the debt position entity;
    • creates it and checks it becomes UNPAID;
    • verifies the notice is present as valid in the GPD/ACA archive;
    • checks the expiration workflow is scheduled.

    a simple debt position created on {pagopa_interaction}

    Creates a simple debt position directly on GPD/ACA (bypassing PU creation):

    • builds the entity and its transfer, generating IUV/NAV/IUPD;
    • posts it to GPD/ACA and asserts the call succeeds;
    • verifies the notice is present as VALID in the GPD/ACA archive.

    a simple debt position with balance created by organization interacting with {pagopa_interaction}

    Like a simple debt position created by organization..., but with a balance set to the installment; creates it and checks UNPAID status, presence in GPD/ACA and the scheduled expiration workflow.

    the previous payment of installment {seq_num} of payment option {po_index}

    Given that plays a full payment-and-reporting cycle for one installment and checks the outcome:

    • pays the installment and checks the receipt is processed;
    • checks the other payment options become INVALID;
    • uploads the payment reporting and checks the installment becomes REPORTED;
    • uploads the treasury file and checks it is processed;
    • checks the payment option and debt position become PARTIALLY_PAID;
    • checks the resulting classification labels.

    the successful payment of the installment

    Performs a full successful payment in one step:

    • pays the installment,
    • checks the debt position becomes PAID
    • checks the receipt is processed correctly.

    the successful payment of the installment created outside PU

    Like the successful payment of the installment, but pays the first installment of a debt position created outside PU, then checks the PAID status and that the receipt is processed.
